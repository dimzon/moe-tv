Спасибо за интерес к проекту! Приветствуются правки любого размера — исправления ошибок, новые

> изменении и кредиты, которые должны остаться нетронутыми.

## Основные правила

- МОЁ ТВ — **только плеер**, и притом **только прямой эфир RuTube**. Никаких встроенных каналов,
  плейлистов, подписок и контента, никаких провайдеров «принеси свой источник» и ничего, что
  облегчает доступ к несанкционированным трансляциям.
- Цель — **Android TV** (сначала пульт / leanback). Навигация должна оставаться удобной с пульта.
- Следуйте принятому стилю и структуре кода (Kotlin, Jetpack Compose for TV, Koin, Room).
- Никогда не удаляйте и не переписывайте унаследованные уведомления об авторских правах, лицензии
  и атрибуцию в коде, ресурсах и документации. В новых файлах допустим заголовок
  `// SPDX-License-Identifier: GPL-3.0-only`.
- **Язык документации.** Всё, что адресовано пользователям и контрибьюторам, пишется
  **по-русски**: `README.md`, `CONTRIBUTING.md`, `extras/USER_GUIDE.md`, шаблоны issues/PR,
  `docs/attribution-checklist.md`, `docs/rutube.md`. Юридические тексты (`LICENSE`, `NOTICE`,
  `THIRD_PARTY_LICENSES.md`), исторический `CHANGELOG.md`, комментарии в CI и идентификаторы в
  коде остаются в оригинале: это международная практика, а парсеры release notes ищут заголовки
  `## <тег>` в `CHANGELOG.md`.
- Если вы переводите или правите `PULL_REQUEST_TEMPLATE.md`, **в том же изменении** обновите
  «иголки» (`needle`) в [.github/workflows/pr-checklist.yml](.github/workflows/pr-checklist.yml) —
  иначе проверка обязательных галочек перестанет узнавать шаблон.

## Настройка проекта

1. Установите **Android Studio** версии, поддерживающей **AGP 9.x**.
2. Клонируйте свой форк, откройте проект и дождитесь синхронизации Gradle.
3. Запустите конфигурацию `app` на **эмуляторе или устройстве Android TV**, либо соберите из CLI:
   ```bash
   ./gradlew assembleDebug
   ```

Быстрый обзор кода — в [README](README.md), контракт API RuTube / синхронизации / EPG — в
[docs/rutube.md](docs/rutube.md), более широкий справочник по дизайну — в
[`extras/OwnTV_Master_Product_Brief.md`](extras/OwnTV_Master_Product_Brief.md) (унаследован от
апстрима).

## Рабочий процесс (коммиты идут в `main`)

Исходники форка открыты на <https://github.com/dimzon/moe-tv>; ветка `main` — основная
(`origin` настроен по SSH). Работа и коммиты идут прямо в текущей ветке `main`.
**Не создавайте ветки** (`git checkout -b`, `git switch -c`, `git branch <имя>`,
`git worktree add -b`) без явного указания — см. [AGENTS.md](AGENTS.md). Через публичный
репозиторий работает обычный поток «форк → PR → ревью».

1. Внесите изменения и **закоммитьте** их с понятными сообщениями — из них собирается changelog
   релиза, так что пишите для читателя (например, `Исправлена рассинхронизация сетки EPG при
   навигации пультом`).
2. Запустите проверки, которых касается правка (юнит-тесты, гейт i18n, компиляцию).
3. Если публичный remote появился — запушьте и откройте Pull Request; перед слиянием CI должен
   быть зелёным.

> **Как устроен CI.** На каждый push и PR в `main` работает `check` (юнит-тесты + lint) — это и
> есть гейт. Сборка APK занимает ~11 минут и запускается только на тегах `v*` (релиз) и вручную
> через Actions → *Run workflow* (`workflow_dispatch`), если нужен dev-APK. На обычных пушах
> она не запускается, чтобы не отменять сама себя и не держать ветку красной.

> Один коммит / PR — одна задача. Небольшие, удобные для ревью изменения вливаются быстрее.

## Сообщения коммитов

- Повелительное наклонение: «Добавить…», «Исправить…», «Отрефакторить…».
- По возможности одна логическая правка на коммит.
- Для коммитов только с документацией или конфигами, которым не нужна сборка, добавляйте `[skip ci]`.

## Сообщения об ошибках и предложения

Заводите issue с описанием ожидаемого и фактического поведения, модели устройства / версии Android
TV и шагов воспроизведения. Для проблем с воспроизведением очень помогает лог (`adb logcat`).
