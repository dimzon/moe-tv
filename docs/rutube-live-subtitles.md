# RuTube live TV: subtitles (captions) — research + rescan procedure

Date: 2026-11-10. Branch `remove-mpv` (worktree `C:\Work\OWNTV-remove-mpv`).

## Why this doc

OWNTV removed mpv and all VOD; the app is live-TV-only on ExoPlayer. The question was:
does RuTube linear TV have subtitles at all, and how would we show them?

## Mechanism (from the SmartRuTube reference app, `C:\Work\SmartRuTube`)

Subtitles for a broadcast are NOT in the HLS manifest and NOT CEA-608/708 in the TS
(SmartRuTube even filters CEA mime types out of its subtitle menu). They come as **sidecar
files advertised by the play-options API**:

1. `GET https://rutube.ru/api/play/options/{videoId}/?no_404=true&pver=v2&referer=https%3A%2F%2Ftv-androidtv.rutube.ru`
   with UA **`com.rutube.mobile/31.18.0 (Android 13)`** (desktop UA gets 404).
   TV items go through the same endpoint as VOD; TV params only strip the ad schedule.
2. Response field **`captions[]`**: `{sub_id, format, langTitle, file, is_autogenerated, code}`.
   `format` is `srt` or `vtt` (anything else is skipped by SmartRuTube); `file` is a ready
   URL on `pic.rtbcdn.ru`, no auth needed.
3. SmartRuTube side-loads each file: `SingleSampleMediaSource` merged with the `HlsMediaSource`
   via `MergingMediaSource` (`common/.../ExoMediaSourceFactory.java:66-120`); mime
   `srt`→`application/x-subrip`, `vtt`→`text/vtt`; subtitle delay = `copyWithSubsampleOffsetUs`.
   Selection persists per profile; the CC button appears only when `captions` is non-empty
   (`VideoLoaderController.showSubtitleButton(hasSubtitles)`).

## Empirical scan (all channels, anonymous, proxy disabled)

`tools/scan_rutube_captions.py` (same endpoints/UA as the app; bypasses any proxy at two
levels; writes `scan_results.json`). Result at scan time:

- channel list `/api/v2/video/stream/tvbroadcastinfo/?client=tv&tvprogramm=false` → **246** channels;
- play-options for **every** one: **`captions: []`** — 246 without, 0 with, 0 errors.
- Live responses DO carry the field (`stream_type: "broadcast"`, `live_streams` present) — the
  server simply advertises no sidecar files for the current broadcasts.

Caveats: anonymous (no account); `captions` are per-broadcast — a special event may carry them
later; the scan is a snapshot. **Rescan any time with the script.** A human report of a
subtitled broadcast exists ("я смотрел какую-то передачу с субтитрами") — consistent with
per-broadcast captions, not with channel-level ones.

## OWNTV state / parity

OWNTV's live engine already renders subtitles natively (HLS text renditions + CEA via
ExoPlayer's text renderer + `ExoPreviewSurface`'s SubtitleView + style/delay settings).
What OWNTV does NOT have yet is the RuTube `captions[]` sidecar acquisition (step 1–3 above).
That chain is the follow-up that keeps the "ability to show subtitles" real for RuTube
broadcasts when the server starts returning them. Preserve everything in the PRESERVE list
of `WAVE2_CONTRACT.md` while deleting dead VOD core.
